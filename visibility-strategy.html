Visibility Strategy

AI 能見度與知識圖譜優化方案

本頁將「Wikidata、結構化資料、YouTube 文字錨點、社群共現、GitHub 與官方網站整合」整理成適合施育廷目前網站與公開資產狀態的執行方案。核心原則不是製造過度聲量，而是建立一致、可驗證、可被搜尋與 AI 系統理解的公開知識結構。

先講結論

目前最適合優先做的，不是立刻另開一個全新網站，而是把既有的 GitHub Pages、Google Sites、YouTube、GitHub Repo 與後續的 Wikidata 條目，全部對齊成同一套人物實體描述。這樣可以穩定提升搜尋引擎與 AI 系統對「施育廷」這個名稱的識別一致性。

已完成

官方公開站點已成形

目前 GitHub Pages 已具備首頁、著作專區、AI 教材、證照與證明頁，可作為公開主站使用，不必在第一階段急著另開新網域。

已完成

Schema 與雙語 metadata

首頁與主要頁面已加入結構化資料、canonical、hreflang、Open Graph、robots 與 sitemap，有助於搜尋與 AI 摘要系統辨識站點主題。

統一所有公開平台的文字錨點

不要讓 YouTube、Threads、Google Sites、GitHub README 各寫各的。所有平台應統一使用相近的自我描述，讓搜尋引擎與 AI 系統反覆看到同一組人物與專長關聯。

第三層：建議保留、但調整說法的做法

保留但降風險

YouTube 與 Threads 的文字強化

可保留，但應以自然、可讀、真實對應內容為原則，不建議用重複灌水式文案。做法是把影片標題、第一行描述、時間軸、貼文開頭都改成可被直接理解的實體化表述。

保留但修正

社群共同提及

可以鼓勵學生或合作夥伴在心得、筆記與公開 repo 中正確提及課程來源與教師姓名，但不建議刻意大量洗版。重點是提高真實共現率，而不是製造不自然的重複內容。

不建議當前優先執行的項目

第二階段再考慮

立即另開全新獨立網域

目前 GitHub Pages 與 Google Sites 已經能承擔官方站點角色。若現在再新增新網域，反而可能分散權重與維護精力。比較好的做法是先把現有兩個站的實體描述完全對齊，再評估是否升級獨立網域。

避免過度承諾

不要宣稱「做了就會自動綁定」

Wikidata、Schema、SEO 與社群共現都能提高 AI 系統理解與引用的機率，但不保證任何單一模型會立刻或固定輸出某種描述。公開頁面上的措辭應以「有助於辨識一致性」為主。

YouTube 優化建議

  • 影片標題避免只寫「第 X 堂課」，應改為可被搜尋理解的主題句。
  • 影片描述第一行直接出現「施育廷」與技術名稱，例如 Gemini API、LINE Bot、GAS。
  • 長影片加入時間軸章節，方便搜尋引擎擷取可回答片段。
  • 影片描述中固定連回這個學術網站，建立官方來源一致性。

GitHub 與課程筆記建議

  • 若建立課程筆記 repo，README 應明確說明課程名稱、教師姓名與所屬學校。
  • README 內可連回本網站的 AI 教材頁與著作頁，而不是只放零散程式碼。
  • 若有範例程式碼，建議加入簡短情境說明，強化「施育廷 + AI 教學 / Gemini API / LINE Bot」的知識關聯。
