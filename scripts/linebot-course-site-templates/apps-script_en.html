Security, quotas, and official sources

Security and quotas

Official sources checked: 2026-11-07. Recheck before deployment because quotas may change.

Security: the APIKEY worksheet is a historical example only. Never store secrets in Sheets. Store tokens, Channel Secret, and other API keys in server environment variables or a secret manager. GAS Script Properties holds relay shared-secret and SHEET_ID configuration; it is not a vault. Project editors can retrieve these values, so do not broadly grant editor access.

The documented event fields of public GAS doPost(e) do not expose x-line-signature; pure GAS is not a reliable direct LINE signature-verification entry point. Use Node / Cloud Run to verify the original request body before replying and sending signed records. GAS verifies the relay signature before writing to Sheets; relay verification is not LINE signature verification.

  • Apps Script: 6 minutes per execution, 30 simultaneous executions per user, and 1,000 per script. These are execution limits, not safe user counts or throughput guarantees.
  • UrlFetch: 20,000 calls per day for consumer accounts and 100,000 for Google Workspace, per user; quotas reset 24 hours after the first request.
  • Total trigger runtime, including time-driven triggers: 90 minutes per day for consumer accounts and 6 hours for Workspace. This is trigger usage, not an aggregate daily runtime limit for all web app requests.
  • Google Sheets file limit: 20 million cells or 100MB, not 10 million cells. File capacity does not establish usable throughput or a safe user-count limit.

Batch reads and writes, use locks for shared writes, handle retries and duplicate records, and define retention periods with minimal personal data and restricted access. Measure latency, errors, and quota usage under load. Move high-concurrency, transactional, or fine-grained access-control workloads to a database.

Role of Apps Script

The materials frame the system as a multi-module assistant: LINE handles message intake and delivery, Gemini handles interpretation and generation, Sheets provides memory, Drive stores files, and Apps Script supports workflows. In the quickstart, Node / Cloud Run verifies LINE signatures and replies; GAS verifies signed relay records before writing to Sheets.

How routing works

When LINE sends an event, the Node / Cloud Run entry point first verifies the LINE signature against the raw request body, then identifies the event type, reads user state, selects the target workflow, invokes the required services, records the result, and then replies or pushes a follow-up message.

Worksheets are part of the data architecture

Google Sheets is not just an attachment. In this course, it becomes a lightweight data layer: non-secret configuration, file logs, notes, state flags, and workflow traces are all structured there.

Prompts and intent extraction

The course emphasizes role-based prompting rather than generic text generation. A useful backend prompt should define tasks, constraints, required parameters, clarification behavior, and when structured output is required.

Logs, admin menus, and maintenance

The original materials also discuss admin-side menu control inside Google Sheets. That turns the bot into a maintainable service, which is why this site treats engineering maintenance as part of the learning outcome.
