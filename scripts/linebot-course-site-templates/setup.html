Setup

從零開始建立 LINE Bot 基礎環境

本頁依照原始教材順序，先完成資料層與儲存空間，再設定 LINE 與 Apps Script，最後進行 Webhook 驗證。這樣能降低初學者在設定階段的失敗率。

設定步驟

前置條件 Google Sheet Google Drive LINE Developers Apps Script 佈署 Webhook 驗證

實作回覆Bot與Sheets紀錄

開啟完整快速實作

依序完成Node／Cloud Run驗簽入口、GAS簽名紀錄端與Sheets流程。Python磨課師僅為延伸學習，非必修，也不能替代此實作。

安全原則：APIKEY工作表僅為歷史示例，勿儲存秘密。Token、Channel Secret及其他API金鑰應放在伺服器環境變數或秘密管理器。GAS的Script Properties僅用於relay共享secret與SHEET_ID等設定，不是vault；專案編輯者可取得內容，不可廣發編輯權限。

GAS公開doPost(e)的事件欄位不含x-line-signature，不能作為可靠驗證LINE簽章的直接入口。正式入口須由Node／Cloud Run以原始請求本文驗簽，再回覆Bot並送出簽名紀錄；GAS驗證relay簽名後才寫入Sheets，兩種簽章不可混為一談。

安全、配額與官方來源

前置條件

  • 可登入 LINE Developers 的 LINE 帳號。
  • 可使用 Google Sheets、Drive 與 Apps Script 的 Google 帳號。
  • 基本回覆與Sheets紀錄不需Gemini API Key；啟用AI或其他進階工作流時，才另備服務金鑰並存於伺服器環境變數或秘密管理器。
  • 先想好資料夾、工作表與專案命名方式，避免後續維護混亂。

步驟 1：建立 Google Sheet 作為記憶層

歷史示例警示：上圖APIKEY工作表不建議用於儲存密鑰。勿將秘密存入Sheets；請使用伺服器環境變數或秘密管理器。

教材把 Google Sheet 視為整個系統的記憶層。可依需求準備紀錄、備註、上傳檔案與暫存資料等工作表；APIKEY僅為歷史示例，不應建立為秘密儲存區，讓程式不只是回覆訊息，也能持續保留工作狀態。

步驟 2：建立 Google Drive 儲存空間

Drive 用來接收使用者上傳的圖片、文件、影音，以及後續產生的報告與教材輸出。建議一開始就整理好資料夾層級與存放規則。

步驟 3：建立 LINE Messaging API Channel

先建立LINE官方帳號，在LINE Official Account Manager啟用Messaging API，再到LINE Developers Console開啟對應Channel。將Channel secret與Channel access token設於伺服器環境變數或秘密管理器，勿寫入Sheets。詳細設定與驗證請依完整快速實作進行。

步驟 4：佈署 Google Apps Script Web App

Apps Script在入門架構中是簽名紀錄端。於Script Properties設定relay共享secret與SHEET_ID，再部署Web App；Node／Cloud Run另負責LINE驗簽與回覆。Script Properties不是vault，專案編輯者可取得內容，勿廣發編輯權限。

步驟 5：完成 Webhook 驗證

將Node／Cloud Run驗簽入口網址填入LINE Developers的Webhook URL，勿填GAS網址。啟用Webhook後測試有效簽章、無效簽章拒絕、Bot回覆與Sheets紀錄；Console的Verify成功不代表安全驗簽已完成。若失敗，檢查入口、伺服器憑證、relay簽名設定及工作表ID，勿以擴大編輯權限排除問題。
