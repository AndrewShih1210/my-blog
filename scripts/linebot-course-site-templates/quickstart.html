function reply_message(replyToken, reply, url = 'https://api.line.me/v2/bot/message/reply')
{
UrlFetchApp.fetch(url, {
'headers': {
'Content-Type': 'application/json; charset=UTF-8', // 設定內容類型為JSON
'Authorization': 'Bearer ' + CHANNEL_ACCESS_TOKEN, // 設定認證標頭

'replyToken': replyToken, // 傳送回覆的token
'messages': reply // 設定回覆的訊息內容
}),
});
}

7. 系統指令與主題應用

38-page PDF: 35–38 · 112-page PDF: 99–112

依原教材設定角色、語氣、任務範圍與行為限制。以同一組問題比較調整前後回答，再選擇教學、客服或知識問答主題，不以「看起來能回答」當作測試完成。

檢查點：保存測試問題、預期表現、實際回答與需要修正之處，區分功能正常與內容正確。

架構頁：從回覆Bot延伸到雲端助理

架構頁的首次設定順序為Sheets→Drive→Apps Script→API設定→Drive API→Web App部署→LINE Webhook，接著是管理員選單、檔案問答、報告生成、Threads、搜尋、行事曆、郵件與筆記。這些是基礎投影片後的延伸功能，不另換成雲端伺服器課程。

流程頁：與AI協作開發的學習過程

  1. 需求釐清：分開列出檔案處理與文字指令兩個功能模組。
  2. 提供上下文：交代GAS、Sheets分頁、Drive資料夾與目前程式；一律使用占位符，不提供真實金鑰。
  3. 先請AI畫架構，再逐一實作getLogData、UrlFetchApp呼叫與意圖辨識。
  4. 回報完整但已去識別的程式、錯誤訊息與截圖，再測試、修正、重構。
  5. 開新對話時交接可運作版本與待辦；原文10萬Token門檻是歷史經驗，不是所有模型的固定上限。
  6. 依版本演進追加Flex Message、檔案說明、HTML報告、試算表問答與Threads，而非一次要求所有功能。

與原教材分開的修正註記

  • 第63、78、79、92頁含排版用彎引號，直接貼入程式可能語法錯誤，需改成半形直引號。
  • 第66頁先把訊息加上「你說了：」，再檢查startsWith("!")，會讓群組指令判斷失效；應先檢查原始event.message.text，再組合回覆文字。
  • 第64頁的「內容接下頁」是投影片占位說明；第97頁兩段else是修改前後對照。這些不能當完整程式原封不動貼上。
  • 原教材中的模型名稱、免費額度與介面是當時版本，不應視為目前可用保證；尤其第85頁的舊額度不作為本次更新的數值依據。
  • APIKEY工作表與直接寫入原始碼為原教材做法；公開版應將金鑰管理另外修正。Script Properties可分離設定，但編輯者仍可讀取，並非保管庫。
  • GAS直連Webhook是原教材學習架構，不表示已具備LINE簽章驗證。正式服務仍須補驗證機制；此限制列為安全附錄，不改寫教學主線。
  • 避免把含Token、個人資料或實際聊天紀錄的投影片截圖重新公開。本預覽只選取11張不以憑證／身分／聊天紀錄為內容的頁面。
