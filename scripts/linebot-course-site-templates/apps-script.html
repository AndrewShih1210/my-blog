安全、配額與官方來源

安全與配額

官方資料查核日期：2026-11-07。配額可能變更，部署前請再確認。

安全原則：APIKEY工作表僅為歷史示例，勿儲存秘密。Token、Channel Secret及其他API金鑰應放在伺服器環境變數或秘密管理器。GAS的Script Properties僅用於relay共享secret與SHEET_ID等設定，不是vault；專案編輯者可取得內容，不可廣發編輯權限。

GAS公開doPost(e)的事件欄位不含x-line-signature，不能作為可靠驗證LINE簽章的直接入口。正式入口須由Node／Cloud Run以原始請求本文驗簽，再回覆Bot並送出簽名紀錄；GAS驗證relay簽名後才寫入Sheets，兩種簽章不可混為一談。

  • Apps Script每次執行最長6分鐘；每位使用者同時執行30個，每個指令碼同時執行1,000個。這些是執行限制，不是安全使用人數或吞吐量保證。
  • UrlFetch每日呼叫：個人帳戶20,000次、Google Workspace帳戶100,000次，依使用者計算；配額於首次要求後24小時重設。
  • 時間觸發器等觸發條件的每日總執行時間：個人90分鐘、Workspace 6小時。這是trigger用量，不是所有Web App請求共用的每日總執行時間。
  • Google Sheets目前檔案上限為2,000萬儲存格（20 million cells）或100MB，不是1,000萬儲存格。這是檔案上限，不能推算可用吞吐量或安全人數上限。

實務設計：批次讀寫，使用鎖保護共享寫入，處理重送與重複紀錄；設定紀錄保留期限、最小化個資並限制存取。以實測延遲、失敗率與配額使用量評估負載；高併發、交易或細緻權限需求應轉用資料庫。

官方來源 / Official sources (2026-11-07): Apps Script quotas · Properties Service · Web Apps event fields · LINE signature verification · Google Sheets file limits.

核心元件

  • LINE Messaging API：負責接收使用者訊息與回送內容。
  • Webhook：先由Node／Cloud Run入口驗證LINE簽章，再將簽名紀錄送至Apps Script。
  • Google Apps Script：在本入門架構中驗證relay簽名並寫入Sheets；其他路由、模型呼叫與整理功能屬延伸應用。
  • Google Sheets：作為非機密資料的記憶層與流程紀錄區，不儲存金鑰。
  • Google Drive：存放使用者上傳檔案與系統輸出結果。
  • Gemini：負責摘要、分類、生成與問答等 AI 任務。

資料流怎麼走

一則LINE訊息進來後，先由Node／Cloud Run入口以原始請求本文驗證LINE簽章，再處理事件及回覆；入口另將簽名紀錄交給GAS驗證後寫入Sheets。延伸流程可依事件、使用者狀態與指令讀取工作表、呼叫Gemini或存取Drive。這代表設計重點不只是回覆語句，而是整個判斷與寫入流程。

管理與紀錄

如果把 Bot 用在教學或行政情境，管理功能比回覆效果更重要。應至少規劃使用紀錄、錯誤紀錄、上傳檔案對應表與人工介入節點，由Google Sheets與Apps Script維持非機密資料；API金鑰則另由伺服器環境變數或秘密管理器管理。

練習建議

  • 畫出一張自己的資料流圖，標出訊息入口、判斷點與輸出位置。
  • 列出至少三張你要建立的工作表，說明每張表的用途。
  • 思考哪一些功能一定要寫入紀錄，哪一些可以只即時回覆。
